2. 性能差の解釈

Face判定
候補はprecision寄りで、no-faceを安全に棄却する代わりにface-positiveを多く落とす。 同一805 supervised Headで候補はTP 726 / FP 4 / FN 40 / TN 35。 指定資料に対しfalse-face rateを12.84 pp下げた一方、face-present recallは2.12 pp低い。 Face-positiveが766件、no-faceが39件と約20:1であるため、5件分のfalse-face改善より 16件分増えたface missの影響が大きく、macro F1は0.0197低下した。
楕円
平均的な重なりは互角だが、候補はパラメトリックな位置・姿勢推定が安定する。 mean IoUは+0.0020に留まり、medianとIoU≥.75は約1 pp低い。一方、P10は+2.11 pp、 center NME・長短軸誤差・角度誤差はすべて改善した。 直接5値を回帰するDEIM ellipse headは、極端に悪い下位例と中心・角度には強いが、 latent mask momentsほど高IoUの輪郭を量産してはいない、と解釈できる。
5点位置
Query Refinementの利得は「おおよその発見」より「厳密な位置合わせ」に現れる。 F1@.05は+3.10 ppだが、F1@.10は+0.24 ppまで縮む。 すなわち、.10以内に入る点数はほぼ同じで、その点をさらに中心へ寄せる能力が高い。 二段のcoordinate-conditioned local samplingという構造と、matched NME 33.1%低下が整合する。
遮蔽点
visibleでの改善が大きく、occludedでは改善幅が小さい。 visible NMEは39.3%低下したのに対し、occluded NMEは9.9%低下に留まる。 Query Refinementの局所samplingは画像証拠が見える点に特に有効であり、 遮蔽点ではsemantic queryの全体文脈に依存するため、局所補正の上積みが限定されると考えられる。
機能契約
座標精度の優位は、Head-centric multi-task modelとしての上位互換を意味しない。 候補はHead boxを出さず、point stateも二値である。評価時はGT HeadをanchorにしてFace予測を対応付けたため、 この比較から候補のHead APは得られない。また、occluded座標NMEは計算できても、 occluded / visible状態そのもののF1やoccluded E2E state F1は計算できない。
総合判断
Face ellipseと5点座標が主目的なら、DEIMv2-L + QRは有力である。 特にfalse-face抑制、楕円パラメータ、厳密な点位置で価値がある。 一方、face recall最優先、Head box必須、または遮蔽状態まで下流で利用する場合は、 現構成のまま指定資料モデルを置換する判断はできない。

4. タスク定義と出力契約

入力画像を960へ前処理し、DEIMv2-Lが1クラスのFace候補を出す。 各候補はscore、Face bbox、および (cx, cy, major radius, minor radius, angle)の楕円を持つ。 score 0.33を運用点とし、最大100候補を保持する。

後段は予測楕円の長軸方向へ整列した正方形領域を scale = 1.25で切り出し、256×256へwarpする。 Query Refinementは left_eye, right_eye, nose_tip, left_mouth_corner, right_mouth_corner の5座標と5個のpoint-existence logitを返す。座標を逆変換して元画像へ戻す。

「Query Refinement」はDEIM detector queryの再更新ではない。 検出後に別networkをFace cropごとに実行し、5個のlandmark queryが予測した座標を 二段の局所samplingで補正する処理を指す。

統合時の採用設定: HeadとFaceは、画像全体に対して1回だけ実行する DINOv3 ViT-S+/16（28,697,472 parameters）の特徴を共有する。 共有特徴からHead detection branchとFace / ellipse branchを分岐し、 Keypointだけは楕円整列した256×256 Face cropを専用DINOv3 ViT-S/16へ入力する。 したがって統合後もDINO parameter setは 全画面Head/Face共有用とKeypoint crop用の計2セットとする。
RGB image → shared full-image DINOv3 ViT-S+/16 → {Head branch, Face + ellipse branch} → ellipse-aligned crop DINOv3 ViT-S/16 → Query Refinement

この共有構成は採用する設計仕様であり、本報告の保存済み性能値は現行のDEIMv2-L Face / ellipse + Query Refinementを baseline-aligned評価した結果である。Head branch統合後の精度・parameter・latencyは未評価であり、既存値へ混入させない。 なお、待機中の協調型3段階構成には、Head・Face・full-frame Landmark Queryが 同一ViT-S+/16を1回だけ実行する実装を適用済みである。 これは本節のellipse-aligned crop型Query Refinementとは別実験であり、その未評価値も本表には混入させない。

5.1 DEIMv2-L ellipse detector

BackboneはDINOv3 ViT-S/16（patch 16、embed 384）。block 5 / 8 / 11へSTA interactionを置き、 hidden 224の3-level特徴を生成する。Hybrid encoderはstride 8 / 16 / 32、8 heads、 FFN 896、encoder 1 layer。DEIM transformer decoderはhidden 224、4 layers、8 heads、 FFN 1792、300 object queries、100 denoising queries、reg_max=32である。

Ellipse headは各Face queryから中心、長短軸、角度を直接推定する。 学習lossはcenter、axes、periodic angle、36点contour Chamferを組み合わせ、 円に近い場合は角度の不定性を考慮する。

5.2 Query Refinement

256×256 cropを独立したDINOv3 ViT-S/16へ入力し、最終feature [B, 384, 16, 16]を1×1 projectionで256 channelへ変換する。 5個の学習可能semantic queryを4層decoderへ入れ、各層でself-attention、 spatial memoryへのcross-attention、FFNを実行してbase座標を得る。

続く二つのrefinement stageでは各点周辺を3×3 bilinear samplingする。 第1段はfeature-cell半径2、最大変位0.08、第2段は半径1、最大変位0.04。 query feature・局所feature・現在座標からbounded residualを推定し、 座標とexistence logitを段階的に更新する。

7. データ、分割、学習

候補は固定のgroup-stratified-balanced 8:1:1系splitを使用する。 DetectorはFace annotation、Query Refinementは有効なellipse・keypointを持つFace instanceで学習する。 Test性能の比較だけは、指定資料と同じV3 Head annotationへbaseline-aligned evaluatorで写像した。

7.1 Detector training

Public COCO DEIMv2-L checkpointからclass headを除いて初期化し、DINOv3を含めてfull-unfreezeした。 seed 0、70 epochs、batch 4 × accumulation 4、AdamW、flat-cosine、AMP、EMA 0.9999。 Val ellipse mAP [.50:.95]でepoch 45の best_val_ellipse_map.ptを選択した。Testでcheckpointを選んでいない。

7.2 Query Refinement training

Detector checkpointからDINOv3の188 tensors / 21,614,992 elementsをstrict転送した。 seed 42、batch 32 × accumulation 2、最大150 epochs、backbone LR 1.25e-5、 head LR 5e-4、AdamW、5 epoch warmup、最初の5 epochsだけbackbone freeze、EMA 0.9998。 Val NMEでepoch 73を選び、minimum 100 epochs到達後に終了した。学習時間は2,734.5秒。

座標はpresent点へのWing loss（weight 2.0）、existenceはBCE（0.1）。 decoder中間座標にauxiliary loss（0.5）、二段refinementへ後段重視のauxiliary loss（0.75）を与える。 crop augmentationはscale jitter 0.2、center jitter 0.08、rotation ±25°、flip 0.5、 color・blur・synthetic occlusionを含む。
