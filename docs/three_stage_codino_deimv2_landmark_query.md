# Shared ViT-S+/16: Co-DINO → DEIMv2-L → Landmark Query experiment

## Scope

### Experiment objective contract

There are two distinct experiment objectives, and their results must not be
presented as if they answered the same question:

1. `cascade_comparison`: select the most promising causal cascade. DINO +
   Co-DINO is trained first, then frozen; FACE is trained next, then frozen;
   keypoint/refinement is trained last. This isolates cascade design effects
   and reduces upstream drift. It is a model-selection experiment, not the
   headline end-to-end performance result.
2. `final_performance`: take a cascade selected by the comparison above and
   jointly fine-tune the complete model. DINO, Co-DINO HEAD, FACE, keypoint,
   association, and refinement may all update under explicitly configured
   differential learning rates. Only this later run may be used for the main
   end-to-end performance claim.

Every implementation records `experiment_objective.type`, `claim_scope`,
`joint_fine_tuning`, and `final_performance_claim` in its resolved config,
checkpoint, schema-gate artifact, and W&B config. A stagewise `train.stage`
configuration is rejected unless its objective is `cascade_comparison` and it
disclaims joint/final performance. The currently active HEAD -> FACE ->
keypoint curriculum is therefore a cascade-comparison implementation. The
joint fine-tuning run is intentionally not scheduled until the cascade winner
has been selected on validation.

This experiment evaluates a strict, causal three-stage cascade with one shared
full-frame DINO invocation:

1. DINOv3 ViT-S+/16 processes the full image exactly once;
2. its stride-16 semantic feature feeds the compact Co-DINO `HEAD` branch;
3. expanded `HEAD` ROIs mask the shared encoded feature pyramid before
   DEIMv2-L detects `FACE`;
4. expanded `FACE` ROIs mask the original shared encoded feature pyramid
   before Landmark Query detects keypoints.

This ordering is enforced in the model, not only in post-processing. The
cooperative decoder permits the causal `FACE -> keypoint` update and rejects
the reverse `keypoint -> FACE` update. Inference and val/test use internal
predicted HEADs and predicted FACEs with no ground-truth fallback. During
training, the FACE stage uses square GT HEAD ROIs and the keypoint stage uses
square GT FACE ROIs. Both ROI stages use 1.25x context expansion plus randomized
center and log-scale perturbations, while the Co-DINO HEAD branch is optimized
by its own detection loss.

For this independently trained cascade, predictions made on the same train
records used to fit the preceding detector are forbidden as downstream
training ROIs. Such in-sample predictions are optimistically biased and do not
represent deployment errors; using them as if they were production-like inputs
would leak the preceding stage's train-set fit into the next stage. Both
downstream stages therefore use only GT-derived, perturbed ROIs. The
perturbations protect against learning only perfectly aligned GT crops.
Validation and test predictions are never used as training supervision or for
training-time ROI generation. A future predicted-ROI experiment would require
out-of-fold predictions generated by a preceding model that did not train on
the corresponding record.

The DINO backbone is not invoked for either ROI. The ROI masks are applied to
the already encoded shared feature pyramid, so the full-image DINO execution
count remains exactly one. The independent outputs remain available as
diagnostics, but deployment output is filtered through the preceding HEAD and
FACE stages.

The shared branch omits the standalone SFP P6 projection because
`CompactCoDINO` consumes P3/P4/P5 and constructs its encoder P6 internally.
The model contains one DINO module, not three. A common square-input
standalone HEAD model is now trained once upstream. Its compatible P3/P4/P5
SFP and compact Co-DINO tensors initialize this integrated branch; the
standalone DINO backbone is not instantiated inside the Three-stage model.
The same upstream checkpoint produces the predicted-HEAD caches consumed by
the separate HEAD-crop cooperative architecture.

The common standalone HEAD component is 38,529,172 parameters, including its
own 28,697,472-parameter DINO. It is trained once, not once per downstream
architecture, and its complete detector is never nested inside Three-stage.

## Matched comparison

The two arms are:

- baseline:
  `configs/three_stage/codino_deimv2_l_landmark_query_baseline.yaml`;
- introduced:
  `configs/three_stage/codino_deimv2_l_landmark_query_hpg.yaml`.

Both arms use `face_pose_drive_v2_balanced_811`, the exact same
source-video-balanced train/val/test annotations, internal shared HEAD branch,
public DEIMv2-L task initialization, seed 42, augmentation, epoch budget,
batch policy, optimizer policy, early stopping, and fixed evaluation
thresholds. The introduced arm alone enables the frozen SixDRepNet360 pose
encoder, canonical 3D geometry, pose-query injection, and uncertainty-gated
fusion.

This is a matched one-seed comparison. It is suitable for an initial
engineering decision but does not support a statistical-significance claim.

## Leakage controls

- Co-DINO HEAD supervision is generated from train records only.
- Validation/test HEAD detections come from the internal shared branch; GT
  HEAD fallback remains forbidden.
- Any deployment HEAD threshold must be selected on val and frozen before
  test. The model retains a low score floor during PR-curve collection.
- Cooperative checkpoints are selected by validation loss.
- Test is evaluated only after the training and validation jobs complete.
- Configs record the split, seed, S+ checkpoint path/hash, and COCO checkpoint
  hash. Audit/overfit success markers are distinct from diagnostic reports.

## Scheduled execution

The canonical tests-first queue is:

```text
configs/training_queues/pending_models_tests_then_training.yaml
```

Each strict three-stage architecture must pass schema, GPU-step architecture,
real-data overfit, and small-scale gates before its production job can start.
The schema gate rejects a parallel configuration, predicted training ROIs, a
reverse keypoint-to-FACE path, or accidental use of the separate pixel
HEAD-crop dataset. The GPU-step gate verifies the actual execution order, ROI
sources and finite feature coverage. The order is:

1. all architecture gate groups;
2. one contiguous production-training group;
3. validation/test evaluation and comparison reports.

The legacy standalone jobs in this historical YAML remain disabled. Active
shared-component training and the HEAD-crop architecture are defined only in
the canonical tests-first queue.

The final machine-readable and Markdown comparison files will be written to:

```text
outputs/experiments/three_stage/codino_deimv2_l_landmark_query_comparison_seed42/
```

Until those completion markers exist, no performance result should be claimed.
